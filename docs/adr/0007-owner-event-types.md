# Типы встреч: список и создание для сценария владельца

Status: accepted. Date: 2026-10-20. Partially supersedes ADR-0005.

## Context

Сценарию владельца нужны его типы встреч и форма создания нового типа. ADR-0005 запрещал CRUD для Owner/EventType, чтобы не вводить авторизацию и управление пользователями. Список типов уже был в контракте, создания не было; без него владелец не может завести встречу через UI.

## Decision

Owner остаётся фиксированным сидом, CRUD владельцев не вводится. Для EventType в v1 добавлены только список (`GET /api/event-types/?owner_id=`) и создание (`POST /api/event-types/`). Создание принимает `owner_id`, `title`, опциональный `description` и `duration_minutes = 30`; владелец должен существовать, `title` — непустая строка. Редактирование и удаление EventType не вводятся. UI страницы владельца — отдельная статическая оболочка `GET /owner/`; данные и действия идут через те же API.

## Consequences

Плюс: сценарий владельца закрывается минимальной поверхностью API, гость и владелец работают с одним хранилищем, права/авторизация по-прежнему вне v1. Минус: созданные типы живут в памяти и исчезают при рестарте; при появлении авторизации и редактирования потребуется пересмотр модели доступа и контракта.
