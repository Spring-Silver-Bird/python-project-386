# Хранилище в памяти для v1

Status: accepted. Date: 2026-10-20.

## Context

Для v1 нужен работающий гостевой путь без инфраструктуры: `AGENTS.md` п.2 прямо допускает хранение в памяти, а обязательный Postgres вынесен в Out of scope спеки #8. При этом серверные проверки бронирования (уникальность, окно, рабочие часы) должны оставаться настоящими, а не клиентскими. Дополняет ADR-0005: фиксированные сиды живут в том же in-memory store.

## Decision

Booking-и живут в памяти процесса (`calendar_store.py`, dict + счётчик id): создание, листинг, отмена и расчёт доступности Slot работают поверх него. Тесты сбрасывают хранилище фикстурой. Перезапуск процесса очищает данные; персистентность, миграции и мультипроцессная согласованность в v1 не вводятся.

## Consequences

Плюс: нет БД, миграций и внешних сервисов — демо и тесты детерминированы, серверные правила проверяются на реальном хранилище. Минус: данные теряются при рестарте и не разделяются между воркерами; переход на БД — отдельное решение с пересмотром Out of scope, а не тихая замена реализации.
